## 2. 模块化原则

严格按系统划分模块，**跨模块不直接抓对方内部节点**。

| 系统 | 目标脚本目录 | 职责 |
|------|----------------|------|
| 核心循环 | `scripts/loop/` 或沿用 `pit/` + `hub/` | 下潜、回城、死亡结算、日期 / 吐息 |
| 角色成长 | `scripts/actor/`（可由 `player/` + `meta/` 迁） | 烙印、属性点、XP、存档角色字段 |
| 战斗技能 | `scripts/combat/` + `enemy/` | 命中、技能释放、念力扣减、破盾 |
| 物品经济 | `scripts/items/` | 背包、装备、掉落、金币 |
| 世界关卡 | `scripts/world/`（可由 `pit/` 迁） | 生成、生态法则、秘境、锚点 |
| 交互 | `scripts/interact/` | NPC、宝箱、机关、钓鱼、资源点 |
| 界面 | `scripts/ui/` | HUD、面板、地图 |
| 底层 | `scripts/core/` | EventBus、数据加载、Loc、存档、音频 |

**迁移渐进**：不必一次改完路径；新代码按目标目录落，旧文件在 09 债务表中标注。

## 3. 事件系统（总线）

新增 Autoload **`EventBus`**（`res://scripts/core/event_bus.gd`）。

### 3.1 约定

- 模块间解耦通信走总线：**广播或按事件名路由**。
- 节点本地 `signal` 可保留（如 hitbox → hurtbox），**跨系统**一律 `EventBus.pub` / `sub`。
- Payload 用 `Dictionary`，字段名稳定，写进本文件附录。

建议 API：

```gdscript
# EventBus.gd（草案）
func pub(event: StringName, payload: Dictionary = {}) -> void
func sub(event: StringName, target: Object, method: StringName) -> void
func unsub(event: StringName, target: Object, method: StringName) -> void
```

### 3.2 核心事件名（初表）

| 事件 | 典型 payload | 生产者 → 消费者 |
|------|----------------|-----------------|
| `enemy_died` | `id, rank, pos, floor` | combat → loot / xp / quest |
| `xp_gained` | `amount, source` | loot/quest → actor / HUD |
| `core_dropped` | `core_id, grade, quality, pos` | loot → world pickup / log |
| `item_picked` | `item_id, qty` | pickup → inventory / log |
| `skill_cast` | `skill_id, caster, pos, loud` | combat → biome echo / HUD |
| `mind_changed` | `current, max` | actor → HUD |
| `hp_changed` | `current, max` | actor → HUD |
| `gold_changed` | `total` | economy → HUD / bag |
| `erosion_tier_changed` | `tier, value, max` | world → HUD / combat lock |
| `attr_points_changed` | `unspent` | actor → stats panel |
| `quest_progress` | `quest_id, key, value` | world → tracker |
| `secret_unlocked` | `realm_id` | interact → map / log |
| `player_died` | `pos, floor` | actor → loop / UI |
| `returned_to_town` | `reason` | loop → erosion clear / save |

`PitEventLog` 只是 HUD 流水，**不是**总线；可订阅上述事件来刷字。

### 3.3 现状

工程内 **无 EventBus**。跨系统靠节点 signal + `MetaProgress.changed` + `RunSession.floor_changed`。全量迁移放在阶段 D；新系统优先走总线。

## 4. 数据驱动

尽可能将数值、技能、物品、掉落、敌人、生态配成**数据表**，策划改表、程序少动。

### 4.1 目录

```text
res://data/
  imprints.json          # 烙印系、武器池
  weapons.json
  attributes.json        # 换算系数、升级点数
  xp_curve.json
  mind.json              # 念力上限/回复/传送消耗/药剂
  skills.json            # 主动/被动、念力、CD、品阶门槛
  crystal_cores.json
  items.json             # 消耗品/任务物
  equipment.json
  materials.json
  enemies.json           # 含 rank: trash/elite/special/lord
  biomes.json            # 法则参数
  loot_tables.json       # 按 rank 的晶核爆率与品阶权重
  quests.json
  erosion.json
```

格式：**JSON**（可读、好 diff）。若策划更熟表格，可用 TSV 再导 JSON，但运行时只读一种。

### 4.2 加载

- `scripts/core/data_catalog.gd`（或分 Catalog）在启动时只读加载，缓存 `Dictionary`。
- **禁止**把新数值写死在 `player.gd` / `pit_floor.gd` / `character_stats.gd`。
- 本地化字符串可继续 `Loc`，或迁 `data/loc_zh.json`；不要把玩法数值塞进 `loc.gd`。

### 4.3 现状（GDScript const，待迁）

| 表 | 文件 |
|----|------|
| 字符串 | `scripts/core/loc.gd` |
| 晶核 | `scripts/items/crystal_catalog.gd` |
| 材料 / 道具 | `material_catalog.gd` / `item_catalog.gd` |
| 品质色 | `item_tier.gd`（仅 5 档） |
| 区域 / 敌人 | `region_catalog.gd` |
| 念力 / 烙印品质 | `mind_table.gd` |
| 任务 | `quest_defs.gd` |
| 装备白值 | `equipment.gd` |
| 侵蚀 | `erosion.gd` |

残留 `rune_catalog.gd`：废弃，迁完晶核后删除。

## 5. 存档

- 沿用 `MetaProgress` → `user://meta_save.json` 方向。
- v3.0 必增字段：`imprint_family`、`attr_base`、`unspent_points`、`explorer_xp/level`、装备 `grade/quality`、已学技能与品阶、已解锁秘境 / 锚点。
- **废弃字段**：独立 `mind_level`（可读档时折算为角色等级或丢弃）、局内随机 `brand_quality` 作为角色永久烙印。
- `RunSession` 从「一局肉鸽」改为「一次下潜会话」（侵蚀、本地下潜击杀计数、实例种子）。
